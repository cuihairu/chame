# ADR-0007: 可观测性以 slog 门面 + 接口先行

- 状态：已接受（代决，用户可推翻）
- 日期：2026-10-15
- 对应规格：§15、§23 第 7 项

## 背景

§23 要求决定可观测性是只提供抽象，还是同时提供官方指标导出器。

## 决策

- **日志**：以标准库 `log/slog` 为门面；`core/logging` 只定义窄接口（注入 logger，禁全局 logger）。敏感配置不落日志（§12）。
- **指标**：首期只定义指标契约接口（counter/histogram 级别的窄接口），**官方 Prometheus 导出器**作为可选 `infrastructure/observability` 模块在生产基础设施阶段（§19 Phase 7）交付，不进首期依赖。
- **健康检查**：`core/health` 的模型随 Phase 1 落地。

即：抽象首期交付，官方导出器交付但延后到生产阶段，两者分离。

## 理由

- 框架不应绑定监控栈；窄接口让游戏项目自带导出器可行。
- `slog` 是 Go 标准，无需引入第三方日志库，也便于宿主项目桥接自己的日志。
- Prometheus 是 Go 游戏后端事实默认，作为官方导出器首选，但非首期阻塞项。

## 备选方案

- **首期即交付全套 Prometheus 导出**：否。指标口径需要随适配器实现稳定后定义，先交付容易返工。
- **直接采用 OpenTelemetry 全家桶**：否（首期过重）。窄接口不阻碍后续补 OTel 导出器。

## 影响范围

- 模块与适配器只依赖 `core/logging` 的接口类型，不直接 import 监控库。
- 指标命名规范在导出器交付时定义并冻结。

## 测试要求

- 敏感字段脱敏的日志测试（密钥/助记词不出现在输出）。
- 导出器模块交付时：接口契约测试 + 与接口实现的一致性测试。
