# ADR-0005: 事件订阅轮询优先

- 状态：已接受（代决，用户可推翻）
- 日期：2026-10-15
- 对应规格：§11、§23 第 5 项

## 背景

§23 要求决定 EVM/Solana 事件来源是 WebSocket 优先还是轮询优先，并明确断线后的回补方案。

## 决策

**轮询优先**：

- EVM：按块区间 `eth_getLogs` 从已确认游标推进，区间大小可配置。
- Solana：按配置的 Commitment 轮询 slot/签名，从游标推进。

**断线/重启回补方案**：从最后已确认游标加重叠窗口（可配置）重新扫描；重叠区内靠事件唯一标识（§11.3）去重。WebSocket 作为后续优化项接入，不作为首期正确性依赖。

## 理由

- 轮询的失败模型简单：一次轮询失败不丢状态，重试从游标继续；WS 需要 连接生命周期、心跳、断线检测、断点续传的完整配套，首期复杂度不成比例。
- 游标 + 重叠窗口 + 去重的回补语义对两种来源一致，conformance 契约可统一。
- 规格核心要求（§11.5 游标断点续传、§11.6 重组不被静默忽略）与订阅方式正交，轮询同样满足。

## 备选方案

- **WebSocket 优先**：否（首期）。实时性好但正确性依赖连接管理成熟度；作为后续低延迟优化，接入时同样以游标为真相源。

## 影响范围

- 事件源接口（capability/event）按「拉取一段区间」建模，而非推送订阅。
- 重叠窗口与去重标识是公共契约的一部分，两个适配器必须实现。

## 测试要求

- 游标回放与重叠窗口去重的单元测试。
- RPC 瞬断后恢复的故障注入测试（§16.4）。
- EVM 重组场景：重叠窗口内事件被重组丢弃时不静默、按 §11.6 上报。
